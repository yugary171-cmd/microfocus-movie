# 微焦短剧 · 后台管理系统操作说明

- 文档用途：给运营、内容编辑和系统管理员看，说明后台「怎么用」
- 更新日期：2026-08-21
- 写的是当前已经能在后台点到的功能；事故值班、改库、全员锁死恢复请看文末相关文档

后台管的是**内容能不能上架、谁能登录、播放出事故时怎么停、用户额度怎么补**。它不管微信小程序里用户怎么刷视频。小程序和后台都不直连数据库，所有决定以服务端记录为准。

当前阶段以内部体验为主。页面上如果出现「Mock / 内部体验」字样，表示这是演示数据：点发布、审核、补偿都**不会**真正推到微信或广告平台。正式对外放量前，还要过资质、备案、类目、广告和发布闸门。

## 1. 两种角色

登录后左侧菜单会按角色显示。看不见的菜单，不是坏了，是你没有权限。按钮灰掉时，旁边一般会写原因。

| 角色 | 日常干什么 | 不能干什么 |
| --- | --- | --- |
| 内容编辑 | 建剧、填版权、上传分集、审待审队列（含自己的剧）、发布、下架 | 改别人负责的剧、进标签库/运营控制、看审计、管账号 |
| 系统管理员 | 内容编辑的全部能力，且可改任意剧；外加标签库、运营控制、审计、账号 | 绕过版权、媒体就绪或外部流量闸门 |

以前的「内容审核」已并入内容编辑。存量审核账号仍能登录，权限按内容编辑处理。新建账号只提供这两种角色。

系统管理员能做内容操作，不等于一个人就能批准高风险动作。补偿、关熔断、重放回调、补发注销令牌，应有工单和另一人批准。

## 2. 怎么打开后台

本地开发：先启动 API，再启动管理后台（默认 [http://localhost:5174](http://localhost:5174)）。连本机 API 时，后台环境里的接口地址应是 `http://localhost:3000`，**不要**再加 `/api`。

管理后台使用短时 access token + HttpOnly refresh session。浏览器不会把 refresh token 暴露给页面脚本；access token 失效时后台会自动续期一次。关闭标签页后重新打开时，若 refresh session 仍有效，页面会自动恢复登录。账号停用、角色变化、凭据重置或 session version 变化会使旧会话失效，仍需重新登录。

- **演示模式**（没配真实接口地址）：任意符合格式的登录名、至少 8 位密码、6 位数字即可进入。登录名只是标识（例如 `stellan`），不必是能收信的邮箱；已有 `name@company.com` 形式的账号仍然有效。角色下拉只用来体验不同菜单，不是真账号。
- **真实模式**：必须填写登录名、密码，以及手机验证器上正在跳变的 **6 位数字**。不要用扫二维码代替日常登录；二维码只在开通账号时用来绑定验证器。

没有公开注册入口。新同事必须由系统管理员在「账号管理」里创建，再走开通链接。

忘记密码时：

1. 还有另一名能登录的系统管理员 → 让对方在账号管理里做「重置登录凭据」。
2. 所有管理员都进不去 → 不要找隐藏后门。运维按 [管理员应急恢复](./admin-emergency-access.md) 执行公开命令。

## 3. 第一次开通账号（收到链接的人）

系统管理员创建账号或重置凭据后，会得到一条 **24 小时一次性**开通链接。请用受控渠道发给本人，不要发到公开群。

本人打开链接后：

1. 用手机验证器（如 Google Authenticator）扫描页面二维码；扫不了就展开手动密钥抄进去。
2. 设置密码（至少 12 位），再输入验证器当前的 6 位数字。
3. 开通成功后去登录页，用**新密码 + 验证器数字**进入。

密钥和备用信息当场抄进公司密码柜，不要截图发聊天、不要写进仓库。链接用过即废；过期了请管理员重发开通链接，不要重复点旧链接。

## 4. 左侧菜单一览

| 菜单 | 谁能看到 | 用来干什么 |
| --- | --- | --- |
| 工作台 | 所有人 | 只读看板：先看风险，再去别的页面处理。没有新建、发布、熔断等操作按钮 |
| 剧目管理 | 所有人 | 找剧、建剧、进详情编辑 |
| 审核队列 | 内容编辑和系统管理员 | 对待审内容点通过或退回 |
| 标签库 | 仅系统管理员 | 新增、停用/启用、删除（有引用须先替换） |
| 运营控制 | 仅系统管理员 | 停播熔断、补秒数、纠错、重放失败回调、补发注销查询令牌 |
| 审计日志 | 仅系统管理员 | 查谁在什么时候对哪条记录做了什么 |
| 账号管理 | 仅系统管理员 | 加人、改角色、停用、重置登录 |

右上角可退出。退出只清本机登录状态。

## 5. 工作台：每天先看这里

工作台是**只读看板**。登录后默认落在这一页，用来回答「现在能不能对外放量、内容卡在哪、回调和账本有没有着火」。页面上没有新建剧目、发布、审核、熔断、补偿等按钮；发现问题时，用卡片里的文字链接跳到「剧目管理」或「运营控制」再动手。

内容编辑在工作台看到的剧目数量，只统计**自己负责**的剧；系统管理员看全库。右上角若写「演示 Mock」，数字来自本机演示数据，不能当正式运营报表。

建议按页面从上到下看：闸门 → 内容状态 → 回调积压 → 权益对账 → 灰度指标。

### 5.1 外部流量合规闸门

这块回答：**现在能不能把流量放到真实用户身上。** 四项勾选来自部署配置（主体、备案、类目、广告），不是在这一页改的。内部体验即使四项未齐，Mock 流程仍可能走通，但角标会写「禁止外部放量」，不能对外宣传已经上线。

| 你在页面上看到的 | 什么意思 |
| --- | --- |
| 允许外部放量 / 禁止外部放量 | 总开关。四项资质都通过，并且真实点播、微信、广告校验都已就绪，才会变成「允许」。少任何一项都是禁止。 |
| 主体资质 | 运营公司主体和相关证照是否已在配置里标记通过。 |
| 小程序备案 | 微信小程序备案是否已标记通过。 |
| 微信类目 | 短剧类目和内容准入是否已标记通过。 |
| 广告能力 | 流量主和激励广告能力是否已标记通过。 |
| 当前阻断项 | 还缺什么。除了上面四项，还可能出现「真实点播/微信未开」「点播或广告适配还没做完」「广告必须走服务端校验」等。四项勾选都绿、这里仍有字，照样不能对外放量。 |

这一页改不了闸门。要改的是配置和真实接入，不是点勾选。

### 5.2 内容状态

这块回答：**片子卡在流水线的哪一段。** 右上角「N 项待审」是状态为「待审核」的剧目部数，不是审核队列里每一条任务的条数。下面五个数字是当前库里（编辑则是自己名下）各状态有多少部剧。

| 你在页面上看到的 | 什么意思 |
| --- | --- |
| 待审（角标） | 还在等内容审核处理的剧有多少部。去「审核队列」处理。 |
| 草稿 | 资料还在填，尚未提交审核。 |
| 待审核 | 编辑已提交，等审核结论。 |
| 可发布 | 审核和媒体条件已够，内容编辑或系统管理员可以点发布。用户这时还看不到。 |
| 已发布 | 正在给观看端展示（还要版权在有效期内）。 |
| 已下架 | 曾经上过、现在对用户不可见。 |

上传中、处理中、待微信审核、已归档等状态在「剧目管理」的筛选里还能看到，工作台这五个格子不单独展示。点「查看全部剧目」去建剧、改资料或发布，不在工作台操作。

### 5.3 回调积压

这块回答：**云点播或广告平台有没有回执没处理完。** 平台处理完上传、转码、机审或广告结果后，会给服务器发一条「回调」。失败堆在这里。工作台只给数字；真正重放要到「运营控制」（仅系统管理员）。其他角色点「去运营控制处理」会看到无权限提示。

| 你在页面上看到的 | 什么意思 |
| --- | --- |
| 无死信 / N 条死信 | 角标。死信是多次失败、系统不再自动试的回执。 |
| 死信 | 同上，条数。出现死信时，对应通道（点播或微信奖励）会熔断，**不会**因此自动关掉全站播放。 |
| 可重试失败 | 暂时失败、系统还允许再试的回执条数。 |
| 最老未处理 | 仍卡在「已接收 / 处理中 / 可重试失败」里、最早那条已经等多久。显示成秒/分/小时；没有积压时是「—」。死信不计入这一项。 |
| 已开 provider 熔断 | 已经打开的通道熔断个数。卡片说明里会列出名称（例如点播、微信奖励）。不是全站播放总闸。 |

解除通道熔断前，应先在运营控制重放死信并核对账本，不要只把开关拨回去。

### 5.4 权益对账

这块回答：**用户剩下的观看秒数，和发放/扣减流水是否对得上。** 系统会定期用「发了多少秒、扣了多少秒、冻了多少秒」重算余额，**不会改写原来的发放或扣减记录**。对不上会打开账本熔断，暂停新的广告发奖和锁定集播放。工作台不能关熔断，要系统管理员核对后再去运营控制处理。

| 你在页面上看到的 | 什么意思 |
| --- | --- |
| 账本一致 / 账本差异 | 角标。有对不上的笔数，或账本熔断已打开，就显示差异。 |
| 差异笔数 | 最近一次对账发现「对不上」的条数（余额对不上，或广告已完成却没有对应发放记录）。 |
| 差异秒数 | 这些差异加起来差了多少秒（按绝对值合计）。 |
| 完成无 grant | 广告/挑战已经记成完成，但系统里找不到对应的「发放额度」记录。等于用户可能看了广告却没拿到秒数，或记账断了。 |
| 距上次对账 | 最近一次对账距现在多久。从未对过账是「—」。 |

数字来自最近一次对账结果，不是你打开页面时当场重算。

### 5.5 关键灰度指标

这块预留给正式灰度后的播放失败率、权益扣减异常率、完播率。当前服务端标记为**数据源未配置**，页面会明确写「暂无可验证的灰度数据」，**不会用假数字填满**。即便以后显示「数据已接入」，在采样完成前三个指标仍可能是「— / 等待采样」。

不要把 Mock 演示播放当成这些指标。

### 5.6 今日处理原则

这是固定提醒，不是实时数据：

1. 闸门没过，就不要对外放量。
2. 审核通过不能代替视频处理完成。
3. 发布、下架、熔断、补偿都要二次确认并留痕。

### 5.7 在工作台看出问题之后去哪

| 看到什么 | 去哪处理 |
| --- | --- |
| 待审很多、草稿/可发布堆积 | 剧目管理、审核队列 |
| 死信、可重试失败、通道熔断 | 运营控制 → 死信重放（系统管理员） |
| 账本差异、完成无 grant | 运营控制 → 补偿或纠错；通道熔断同样在运营控制关 |
| 禁止外部放量、阻断项未消失 | 配置和真实点播/微信/广告接入，不在后台勾选 |

## 6. 日常上剧（内容编辑）

一部剧要给用户看到，大致是这条流水线：

**建资料 → 填版权 → 传分集 → 处理完成 → 提交审核 → 审核通过 → 管理员发布**

### 6.1 新建或打开剧目

在「剧目管理」按剧名或负责人搜索，或点「新建剧目」。列表里能看到状态、集数、许可资料齐不齐。点「查看 / 编辑」进详情。

编辑只能改**自己负责**的剧。系统管理员可以改任意剧的资料。

### 6.2 基础信息与版权

填写剧名、简介、剧目类型（真人 / 数字真人 / 漫剧，写入观看端频道「真人剧 / AI 剧 / 漫剧」）和标签。标签只能从**当前启用词库**勾选，按主题、情节设定、时代背景、人物、风格、受众分组，弹窗内可搜索，不能随手造词；至少选 1 个、最多 20 个。保存时写入词库 id，同名两组（例如主题「现代」和背景「现代」）不会混。人物/风格/受众（含男频/女频）可以打在剧上并参与搜索，但不会出现在观看端详情和卡片上。剧上若还留着未知 id，必须先去掉才能保存。剧目海报替换原来的封面 URL；推广海报选填。Mock 可用本地 jpg/jpeg/bmp/png（≤10MB）生成预览；真实环境尚未接入海报对象存储，不能靠本地文件冒充已上传。版权一块在保存草稿时可以先空着；一旦开始填写就必须一次补齐权利方、许可编号、生效/到期日、报备号、材料对象键、材料摘要（64 位十六进制）和全部授权勾选。提交审核或发布前仍须版权资料齐全——缺一项会被拦住。

版权原件放在受控的私有存储里。后台和数据库只记引用和校验摘要，不要把合同扫描件贴进工单或聊天。

权利到期后，系统会自动把没有有效权利覆盖的已发布剧下架，并停掉新的播放。不要指望「到期了还能播几天」。

### 6.3 分集与上传

至少要有一集。每集需要媒体就绪，并且转码、机审、人工审核、微信侧审核都通过，才能继续往下走。剧目页只显示集数摘要；点「管理剧集」从右侧打开表格，在抽屉里添加、改标题/时长和选视频。集标题可以空着，观看端会显示「第 N 集」。

- **内部 Mock**：按页面提示完成演示处理即可，不代表腾讯云或微信已经审过。
- **接真实接口后**：详情页可能只允许改剧目资料和新增版权版本，分集标题/时长/媒体会变成只读；内容编辑只能处理自己剧目的媒体审核，系统管理员可以处理全库；上传走短期签名直传到点播，结果等回调，不要刷新页面狂点。

每次上传相关操作都会留下审计轨迹：`UPLOAD_SIGNED` 表示谁为哪部剧的哪一集申请了上传签名，`MEDIA_VERSION_CREATED` 表示谁登记了哪一个媒体版本。当前真实 VOD 尚未完成，所以前者不等于上传成功；后续接入 provider 回调后，再补记成功或失败事件。审计记录只展示剧目、集号、媒体版本、文件标识、阶段和状态变化，不展示签名 URL、Authorization 或其他凭据。

### 6.4 提交审核

资料和分集都齐了，内容编辑在详情页点「提交审核」。按钮不可用时，阅读旁边的原因（缺版权、缺集、状态不对、不是自己的剧等）。

提交后不要再当已经上架。用户在小程序里仍看不到，直到有人点发布。

## 7. 审核

打开「审核队列」，处理自己负责的待审任务。内容编辑和系统管理员都可以审；内容编辑只能审核自己提交的剧，系统管理员可以审核全库，内容编辑**可以审自己提交的剧**。

- 核对成片、权利范围、节目号、文件版本和机审结果。
- 通过可以写说明；退回必须写原因（页面有字数要求）。
- 点确认后结论会记下来。Mock 模式下只记本机浏览器里的演示结论，不会提交真实内容平台；刷新后已通过/已退回的任务不应再出现在待审队列。清站点数据会回到样例。

审核通过不等于已经上架，还要等剧目进入「可发布」，再点发布。

内容审核和媒体审核都会记录审核人、目标剧目/集、内容或媒体版本、审核结论以及前后状态。系统管理员可在「审计日志」按动作、目标、请求编号、操作人或剧目/集资源 ID 检索，追查谁处理了哪部剧的哪一集；历史旧记录没有结构化上下文时仍可按原有 detail 查看。

## 7.1 系统通知

系统管理员可在「系统通知」创建纯文本草稿、编辑草稿并发布给全部登录用户。列表只显示标题、发布人、状态、创建日期和操作；通过「查看」可在右侧抽屉阅读完整正文。草稿可以删除，删除前会要求确认；已发布通知不能直接编辑或删除，需要修正文案时新建通知，旧通知可以撤回。创建、删除、发布和撤回都会留下审计记录。小程序「消息」中的系统通知支持未读和已读状态。

## 7.2 用户反馈

登录用户可以从设置提交反馈；系统管理员在「用户反馈」收件箱查看反馈、修改处理状态、写内部备注并回复用户。回复会作为用户通知出现在小程序消息中。内部备注只供管理员查看，不会返回用户；反馈正文和回复正文也不会写入审计日志。

## 8. 发布与下架

在剧目详情，内容编辑和系统管理员都可以：

- **发布剧目**：服务端会再查一遍闸门、版权是否在有效期、每集媒体和审核是否就绪。缺一项就发不出去。Mock 内部体验可能允许在闸门未齐时走通，仍不能对外宣传「已经上线」。
- **下架剧目**：只有已发布的剧可以下架。紧急内容问题应立即下架，不要先争论文案。

下架、归档后记录还在，后台没有「彻底删一部剧」的按钮。重新上架须再走审核。

## 9. 运营控制（系统管理员）

这一页从上到下是五件高风险事，每件都要填原因，多数会再弹一次确认。填工单号和审批人，不要把密码、完整用户资料贴进去。

### 9.1 全站播放熔断

相当于总闸。打开后，**新的播放会被拦住**。内容事故、大面积错扣费时先拉闸，再查原因。恢复前确认故障已处理，并留下恢复依据。解除熔断应有另一人批准。

### 9.2 补偿权益

用户看了广告却没拿到秒数、或客服核验后需要补看时使用。填写用户 ID、剧目 ID、秒数和原因。点下去就是**再发一笔新额度**，浏览器里撤不回。不要用这一步去「改历史发放记录」。

### 9.3 权益纠错

账本只追加、不改旧账。三种类型：

- **冻结剩余**：先把还能播的秒数冻住，避免继续播错。
- **释放冻结**：解冻时必须填原来的冻结记录 ID，不能超过未释放的秒数。
- **核销**：只记「这笔算事故」，**不再改用户余额**。

补偿请用上一栏，不要在纠错里假装改旧发放。

### 9.4 死信重放

点播或广告平台的回调失败堆在这里。可以按「积压 / 死信 / 可重试」筛选。点「填入重放」后补原因，系统把原事件重新处理，**不会复制一笔新奖励或新媒体**。过了保留期、没有可执行载荷时，只能解锁等待平台再推一次。已经成功或已拒绝的事件不能重放。

### 9.5 注销查询令牌补发

用户申请注销后会拿到查询进度的令牌。令牌丢了或过期，客服核验身份后可补发。必须填注销申请 ID 和**同一个**用户 ID。新令牌只显示一次，旧令牌立刻作废。这**不会**帮用户重新登录。

## 10. 标签库（系统管理员）

用来维护剧目可勾选的词。六组都可以新增、停用/重新启用，或彻底删除。不能改名。停用后编辑弹窗里看不到该词，已保存在剧上的 id 不会被改写。删除时：没有剧目引用可以直接删；仍有引用必须选**同一分组**的其他启用词替换，替换会改写已发布剧的标签且不走内容审核版本升级。替换后每部剧至少还要留 1 个标签。

首页筛选和观看端卡片/详情只使用对用户开放的三组：主题、情节设定、时代背景。演示模式下，管理端词库存在本机浏览器里；观看端 Mock 筛选项仍用契约种子，两边不共享。接上真实 API 并完成数据库迁移后，目录筛选项才会跟标签库走同一张表。

## 11. 账号管理（系统管理员）

用来加人、改显示名和角色、停用/启用、重发开通链接、重置登录凭据。没有「彻底删除管理员」；离职走停用。

操作前通常要输入**你自己当前的 6 位验证码**，停用、启用、重发、重置还要写原因。

注意这几条硬规则：

- 最后一个还能正常登录的系统管理员，不能被停用、改成非管理员、或被重置凭据（否则全员进不去）。
- 内容编辑名下还有剧时，停用、重置或改成其他角色前，必须指定一名在职编辑接替。
- 停用或重置后，对方旧的登录状态会失效，需要重新开通或重新登录。
- 不要给自己随便改角色去拿运营或账号权限。

## 12. 审计日志（系统管理员）

可按操作人、动作、目标或请求编号搜索。用来对账「谁在何时发布/补偿/熔断」。日志里不会出现令牌、密码或完整请求体。对账时记下请求编号即可，不要把整页复制到公开群。

## 13. 请不要做的事

- 把 `.env`、密码、验证器密钥、开通链接发给业务同事当「登录说明书」。
- 要求开发做万能密码、跳过验证码、隐藏登录接口。
- 在生产环境长期放置测试验证码或初始化明文密码。
- 用客户端截图当发奖或扣费依据。
- 直接改数据库里的余额或覆盖历史发放记录。
- 把 Mock 演示成功当成真实微信审核或真实广告收入。
- 既执行高风险运营操作又当唯一批准人。
