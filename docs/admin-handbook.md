# 微焦短剧 · 后台管理系统操作说明

- 文档用途：给运营、编辑、审核和系统管理员看，说明后台「怎么用」
- 更新日期：2026-08-19
- 写的是当前已经能在后台点到的功能；事故值班、改库、全员锁死恢复请看文末相关文档

后台管的是**内容能不能上架、谁能登录、播放出事故时怎么停、用户额度怎么补**。它不管微信小程序里用户怎么刷视频。小程序和后台都不直连数据库，所有决定以服务端记录为准。

当前阶段以内部体验为主。页面上如果出现「Mock / 内部体验」字样，表示这是演示数据：点发布、审核、补偿都**不会**真正推到微信或广告平台。正式对外放量前，还要过资质、备案、类目、广告和发布闸门。

## 1. 三种角色，各管各的

登录后左侧菜单会按角色显示。看不见的菜单，不是坏了，是你没有权限。按钮灰掉时，旁边一般会写原因。

| 角色 | 日常干什么 | 不能干什么 |
| --- | --- | --- |
| 内容编辑 | 建剧、填版权、上传分集、提交审核 | 审自己的片子、直接发布、改别人的剧 |
| 内容审核 | 看待审队列，通过或退回 | 发布、下架、改账号、开熔断 |
| 系统管理员 | 发布/下架、运营控制、审计、管账号 | 兼任编辑去改内容、审自己提交的版本 |

系统管理员是「能执行」的角色，不等于一个人就能批准高风险动作。补偿、关熔断、重放回调、补发注销令牌，应有工单和另一人批准。

## 2. 怎么打开后台

本地开发：先启动 API，再启动管理后台（默认 [http://localhost:5174](http://localhost:5174)）。连本机 API 时，后台环境里的接口地址应是 `http://localhost:3000`，**不要**再加 `/api`。

- **演示模式**（没配真实接口地址）：任意符合格式的邮箱、至少 8 位密码、6 位数字即可进入。角色下拉只用来体验不同菜单，不是真账号。
- **真实模式**：必须填写邮箱、密码，以及手机验证器上正在跳变的 **6 位数字**。不要用扫二维码代替日常登录；二维码只在开通账号时用来绑定验证器。

没有公开注册入口。新同事必须由系统管理员在「账号管理」里创建，再走开通链接。

忘记密码时：

1. 还有另一名能登录的系统管理员 → 让对方在账号管理里做「重置登录凭据」。
2. 所有管理员都进不去 → 不要找隐藏后门。运维按 [管理员应急恢复](./admin-emergency-access.md) 执行公开命令。

## 3. 第一次开通账号（收到链接的人）

系统管理员创建账号或重置凭据后，会得到一条 **24 小时一次性**开通链接。请用受控渠道发给本人，不要发到公开群。

本人打开链接后：

1. 用手机验证器（如 Google Authenticator）扫描页面二维码；扫不了就展开手动密钥抄进去。
2. 设置密码（至少 12 位），再输入验证器当前的 6 位数字。
3. 开通成功后去登录页，用**新密码 + 验证器数字**进入。

密钥和备用信息当场抄进公司密码柜，不要截图发聊天、不要写进仓库。链接用过即废；过期了请管理员重发开通链接，不要重复点旧链接。

## 4. 左侧菜单一览

| 菜单 | 谁能看到 | 用来干什么 |
| --- | --- | --- |
| 工作台 | 所有人 | 先看风险：发布闸门、待审数量、回调积压、账本是否对得上 |
| 剧目管理 | 所有人 | 找剧、建剧、进详情编辑 |
| 审核队列 | 仅内容审核 | 对待审内容点通过或退回 |
| 运营控制 | 仅系统管理员 | 停播熔断、补秒数、纠错、重放失败回调、补发注销查询令牌 |
| 审计日志 | 仅系统管理员 | 查谁在什么时候对哪条记录做了什么 |
| 账号管理 | 仅系统管理员 | 加人、改角色、停用、重置登录 |

右上角可退出。退出只清本机登录状态。

## 5. 工作台：每天先看这里

工作台不是报表中心，是「有没有火要先扑」。建议按这个顺序看：

1. **发布闸门**：主体、备案、类目、广告等是否齐。没齐时，内部 Mock 仍可能允许走通流程，但**不能**当成已经可以对外放量。
2. **内容状态**：草稿、待审、可发布、已发布、已下架各有多少。
3. **回调积压**：云点播或广告平台回来说「处理失败」的单子。出现**死信**时，对应通道会熔断（停新奖励或相关处理），但不会自动把全站播放关掉。
4. **权益对账**：系统按发放/扣减记录重算用户剩余秒数。对不上会打开账本熔断，暂停新奖励和锁定播放。对账**不会偷偷改历史记录**，要管理员核对后再关熔断。

处理入口在「运营控制」。

## 6. 日常上剧（内容编辑）

一部剧要给用户看到，大致是这条流水线：

**建资料 → 填版权 → 传分集 → 处理完成 → 提交审核 → 审核通过 → 管理员发布**

### 6.1 新建或打开剧目

在「剧目管理」按剧名或负责人搜索，或点「新建剧目」。列表里能看到状态、集数、许可资料齐不齐。点「查看 / 编辑」进详情。

编辑只能改**自己负责**的剧。系统管理员不在后台当编辑改元数据。

### 6.2 基础信息与版权

填写剧名、简介、分类、标签、封面。版权一块必须认真填：权利方、许可编号、生效/到期日、报备号、材料对象键和材料摘要（64 位十六进制）。还要勾选微信传播、广告变现、转码、物料等授权范围——缺一项，后面提交审核会被拦住。

版权原件放在受控的私有存储里。后台和数据库只记引用和校验摘要，不要把合同扫描件贴进工单或聊天。

权利到期后，系统会自动把没有有效权利覆盖的已发布剧下架，并停掉新的播放。不要指望「到期了还能播几天」。

### 6.3 分集与上传

至少要有一集。每集需要媒体就绪，并且转码、机审、人工审核、微信侧审核都通过，才能继续往下走。

- **内部 Mock**：按页面提示完成演示处理即可，不代表腾讯云或微信已经审过。
- **接真实接口后**：详情页可能只允许改剧目资料和新增版权版本，分集标题/时长/媒体会变成只读，上传走短期签名直传到点播，结果等回调，不要刷新页面狂点。

### 6.4 提交审核

资料和分集都齐了，内容编辑在详情页点「提交审核」。按钮不可用时，阅读旁边的原因（缺版权、缺集、状态不对、不是自己的剧等）。

提交后不要再当已经上架。用户在小程序里仍看不到，直到系统管理员发布。

## 7. 审核（内容审核）

打开「审核队列」，只处理待审任务。

- 核对成片、权利范围、节目号、文件版本和机审结果。
- **不能审自己提交的作品**。
- 通过可以写说明；退回必须写原因（页面有字数要求）。
- 点确认后结论会记下来。Mock 模式下只记演示结论，不会提交真实内容平台。

审核通过不等于已经上架，还要等剧目进入「可发布」，再由系统管理员发布。

## 8. 发布与下架（系统管理员）

在剧目详情：

- **发布剧目**：服务端会再查一遍闸门、版权是否在有效期、每集媒体和审核是否就绪。缺一项就发不出去。Mock 内部体验可能允许在闸门未齐时走通，仍不能对外宣传「已经上线」。
- **下架剧目**：只有已发布的剧可以下架。紧急内容问题应立即下架，不要先争论文案。

下架、归档后记录还在，后台没有「彻底删一部剧」的按钮。需要对外重新上架时，应重新走审核，且执行人不得兼任审核人。

## 9. 运营控制（系统管理员）

这一页从上到下是五件高风险事，每件都要填原因，多数会再弹一次确认。填工单号和审批人，不要把密码、完整用户资料贴进去。

### 9.1 全站播放熔断

相当于总闸。打开后，**新的播放会被拦住**。内容事故、大面积错扣费时先拉闸，再查原因。恢复前确认故障已处理，并留下恢复依据。解除熔断应有另一人批准。

### 9.2 补偿权益

用户看了广告却没拿到秒数、或客服核验后需要补看时使用。填写用户 ID、剧目 ID、秒数和原因。点下去就是**再发一笔新额度**，浏览器里撤不回。不要用这一步去「改历史发放记录」。

### 9.3 权益纠错

账本只追加、不改旧账。三种类型：

- **冻结剩余**：先把还能播的秒数冻住，避免继续播错。
- **释放冻结**：解冻时必须填原来的冻结记录 ID，不能超过未释放的秒数。
- **核销**：只记「这笔算事故」，**不再改用户余额**。

补偿请用上一栏，不要在纠错里假装改旧发放。

### 9.4 死信重放

点播或广告平台的回调失败堆在这里。可以按「积压 / 死信 / 可重试」筛选。点「填入重放」后补原因，系统把原事件重新处理，**不会复制一笔新奖励或新媒体**。过了保留期、没有可执行载荷时，只能解锁等待平台再推一次。已经成功或已拒绝的事件不能重放。

### 9.5 注销查询令牌补发

用户申请注销后会拿到查询进度的令牌。令牌丢了或过期，客服核验身份后可补发。必须填注销申请 ID 和**同一个**用户 ID。新令牌只显示一次，旧令牌立刻作废。这**不会**帮用户重新登录。

## 10. 账号管理（系统管理员）

用来加人、改显示名和角色、停用/启用、重发开通链接、重置登录凭据。没有「彻底删除管理员」；离职走停用。

操作前通常要输入**你自己当前的 6 位验证码**，停用、启用、重发、重置还要写原因。

注意这几条硬规则：

- 最后一个还能正常登录的系统管理员，不能被停用、改成非管理员、或被重置凭据（否则全员进不去）。
- 内容编辑名下还有剧时，停用、重置或改成其他角色前，必须指定一名在职编辑接替。
- 停用或重置后，对方旧的登录状态会失效，需要重新开通或重新登录。
- 不要给自己随便改角色绕过职责分离。

## 11. 审计日志（系统管理员）

可按操作人、动作、目标或请求编号搜索。用来对账「谁在何时发布/补偿/熔断」。日志里不会出现令牌、密码或完整请求体。对账时记下请求编号即可，不要把整页复制到公开群。

## 12. 请不要做的事

- 把 `.env`、密码、验证器密钥、开通链接发给业务同事当「登录说明书」。
- 要求开发做万能密码、跳过验证码、隐藏登录接口。
- 在生产环境长期放置测试验证码或初始化明文密码。
- 用客户端截图当发奖或扣费依据。
- 直接改数据库里的余额或覆盖历史发放记录。
- 把 Mock 演示成功当成真实微信审核或真实广告收入。
- 一个人既当编辑又审自己的片子，或既执行高风险操作又当唯一批准人。
