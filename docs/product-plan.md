技术不变量见 [architecture.md](./architecture.md)。工程进度见 [status.md](./status.md)。外部灰度硬闸门见 [release-checklist.md](./release-checklist.md)。

## 要做的决定

1. 本轮只把已实现的三端做成可内部联调的合规管道，还是继续加功能。
2. 在没有真实剧目和广告准入之前，用什么方式学习用户是否接受「看广告换继续看」。
3. 免费集数、600 秒、24 小时、按剧隔离，哪些是上线前可调参数，哪些是账本底线。

**建议：** 选「有界收口 + 并行验证内容/广告」，在出现真实观看行为之前不加推荐、会员、跨剧额度或新后台模块。

## 问题（不要用功能代替问题）

微信里想免费看完整短剧的人，看完试看后需要一种可重复、可审计的继续观看方式；平台需要在激励广告收入、内容授权和监管之间活下来。

当前 workaround 是去抖音/红果等已有免费短剧产品，或付费/会员。本计划**没有**访谈或行为证据证明用户会为「微光」改路径；Android 参考仓只说明一种产品流程存在，不能证明微信小程序里同一套秒数规则会被接受。

## Android 参考：参考了什么、明确不参考什么

公开参考仓是 [IronManyz/qg_android](https://github.com/IronManyz/qg_android)（青果短剧）。2026-08-12 起的工程决定是：**参考用户路径，不移植实现。** 2026-08-13 补充：**观看端 UI 可以参考其公开界面节奏，但必须自绘，并从 iconfont 选图标；不得复制该仓资源。** 该仓无法改成微信小程序。

青果实际是 Android 模板工程加上穿山甲/字节短剧 SDK（DJX）的壳：剧场、推荐流、播放和解锁都由 SDK 提供，公开 README 称为「免后台」。继续看有三条路——激励广告、会员、单剧付费——单位是**按集解锁**（代码里免费集数和解锁集数还有两套不一致的默认值）。应用自己几乎没有权益账本。HTTP 层主要是登录类模板接口。README 限定学习用途、商用需授权；公开构建配置里还有第三方客户端密钥，不得复制进本仓库。

| | 青果 Android | 微光 |
| --- | --- | --- |
| 内容 | 穿山甲短剧资源 | 自有成片 + 腾讯云 VOD + 自建后台 |
| 继续看 | 广告 / 会员 / 单剧付费，按集解锁 | 仅激励广告；按秒入账、24h、按剧隔离 |
| 事实来源 | DJX SDK | Nest 账本 + 短播放凭证 |
| 后台 | 宣称免后台 | 审核、权利、熔断是一等能力 |
| UI | Android 沉浸暗色剧场 + SDK 播放器 | 微信小程序自绘；PC 管理端不模仿 App |

**可以吸收**

- 用户路径：先免费试看，再拦截，再用一次完整广告换继续看。
- 拦截文案优先说「还可看约 N 集」，而不是只说 600 秒。这只改文案，不改账本。
- 观看端信息架构：封面剧卡（封面 + 标题 + 角标如「新剧」）、首页分栏、播放中途拦截弹层、看广告作为主按钮。
- 暗色背景、暖色强调、大封面、少装饰。现有小程序 token（深底 `#0b0c0f`、强调 `#ffcf5a`）可以继续用，与该方向相容。

**明确不吸收**

- 源码、XML 布局、截图原图、字体、APK、闭源 SDK、穿山甲媒体配置、仓库里的第三方密钥，以及 `drawable` / `mipmap` 里的图标。
- 把穿山甲剧库当内容来源，或在小程序里嵌 DJX/穿山甲短剧 SDK。
- 免后台、客户端解锁即生效、会员/单剧支付，以及解锁弹窗上的「买会员 / 单剧付费」入口（首版只保留看广告）。
- 把青果能上架 Android 市场，当成微光在微信里已经验证过需求。
- 把 Android 视觉套到 PC 管理后台。

### UI 与图标

适用范围：**仅微信观看端**。管理后台保持现有 PC 工作台样式。

公开截图在青果 README 的 `imgs/`（首页剧场、列表、播放）。可对齐的节奏：竖版大封面、圆角剧卡、封面角标、底部主导航、拦截时居中/底部弹层、主操作对比足够。不要像素级临摹，不要使用其品牌名或「青果」素材。

图标统一从 [iconfont 阿里巴巴矢量图标库](https://www.iconfont.cn/search/index?q=%E6%99%BA%E8%83%BD%E4%BD%93&searchType=icon) 选用，导出 SVG 后放入小程序本地资源，并遵守该图标的授权说明（署名、商用限制以页面标注为准）。用户指定的检索入口是「智能体」；剧场、播放、解锁、历史、分类等场景仍在**同一站点**用对应关键词另搜，不从青果仓库抠 PNG。Tab 图标用双色或线性一套，选中/未选中成对；不要 emoji 或系统乱码字符充当正式图标。

本轮工程收口仍不加新页面。改小程序文案或拦截弹层时再套用上述视觉；不为「更像青果」单独开一轮视觉重构。

青果只证明「广告解锁短剧」在 Android 壳产品这条路上存在；不能证明自有版权剧 + 微信激励广告 + 秒数钱包会成立。首版继续只做广告换时长；会员和支付列为 Later，需单独决策。

## 证据台账

- **已知：** 前 2 集免费、一次广告 600 秒、24 小时过期、按剧 FEFO 账本已写入代码与契约；三端 MVP 已落地；真实 VOD 签名与激励广告服务端验证仍 fail-closed；发布与生产启动受合规闸门约束。
- **声称：** 该产品计划此前已确认。仓库内无用户研究、内容供给合同或类目批复。
- **假设：** 用户能理解并接受按剧秒数；能拿到含微信传播与广告变现授权的成片；激励广告有填充；600 秒能覆盖继续观看且单位经济不长期为负。
- **未知：** 精确目标用户；单集时长分布；eCPM 与填充；内容从哪来；微信是否提供可信广告服务端验证。

## 目标用户与场景（暂定，待打脸）

首个可测试画像（不是市场结论）：

- 在微信内打开小程序、愿意先看免费集的短剧观众
- 触发：试看结束，想继续看同一部剧，但不想立刻付费
- 期望进展：用可接受的一次完整激励广告，换一段明确、会过期的继续观看时间

明确不作为首版承诺的用户：要跨剧通用额度的人、要会员去广告的人、要在管理端小程序里办公的运营。

## 期望结果

在内容与广告能力允许的最小灰度里，验证三件事：

1. 第 2 集能看完（内容与播放是否成立）。
2. 看完试看的人愿意完整看完一条激励广告（交换是否成立）。
3. 看完广告后 24 小时内会回到**同一部剧**继续看（按剧钱包是否成立）。

在没有基线前，**不把**「500 激活 / 14 天 / D7=5%」当作已验证的成功线。那些数字保留在发布清单里，仅作未校准护栏，等第一批真实剧目校准后再升格为决策阈值。

内部阶段只看领先指标是否**有定义、能记下、能复盘**，不要求证明商业模式。Mock 广告**不能**当作收入证据。

## 规则：底线 vs 可调参数

账本必须可审计，数值可以在灰度前改，但改之前要记一次决策。

| 类型 | 项 | 说明 |
| --- | --- | --- |
| 底线 | 服务端是余额与播放许可的唯一事实来源 | 客户端不能改余额、不能持有长期播放地址 |
| 底线 | 奖励按不可变批次发放，不覆盖汇总余额；消费 FEFO；不出现负余额 | 见架构不变量 |
| 底线 | 免费集不扣权益；暂停/缓冲/后台不扣费 | |
| 底线 | 无资质、无逐剧权利、无真实 provider 时不得对外流量 | |
| 可调（v0 默认） | `FREE_EPISODE_COUNT = 2` | 可用文案和数值实验，不改账本模型 |
| 可调（v0 默认） | `REWARD_SECONDS = 600` | 应对用户说「还可看约 N 集」，避免只说秒数 |
| 可调（v0 默认） | `REWARD_TTL_SECONDS = 24h` | 过期文案必须可见 |
| 可调（v0 默认） | 额度仅限当前剧 | **最高风险的欲望假设**；未验证前不做跨剧通用池 |
| 实现约束 | 单活租约、5 秒心跳、15 秒断网宽限 | 优先观察是否误伤正常切聊天，而不是先加更严风控 |

产品与内容（与工程并行，不阻塞提交）：

**结果：** 真机跑通主路径，暴露可用性与风控误伤。

## 首版用户路径

1. 打开小程序 → 看到内部体验标识（Mock 时）→ 选一部剧。
2. 看完前 2 集免费内容；进度保存；暂停不扣费。
3. 第 3 集起被拦截，说明「看完一条广告，为本剧增加约 N 集、24 小时内有效」。
4. 广告未完成 / 无填充：不发奖，允许重试，已有额度不动。
5. 广告完成：服务端入账一笔 600 秒批次；播放继续按媒体进度扣减。
6. 额度耗尽或过期：暂停并保留进度；过期批次不再可用。
7. 运营侧：权利与审核通过才能发布；下架立即停发新凭证。

## 验收

### 工程收口（Now）

- 契约与测试在当前工作区可复现通过
- 空白或本地 MySQL 能 migrate / seed（在 Docker 已就绪时）
- 生产路径仍 fail-closed：无真实 provider 实现不得对外

### 产品学习（Now–Next）

- 未看完广告的人**说得出**为什么没得到额度
- 看完广告的人**说得出**额度只用在这部剧、何时过期
- 切到微信聊天再回来，播放与扣费符合「暂停/后台不扣、超 15 秒需续租」的预期，或记录为缺陷
- 内容盘点表列出每部候选剧缺哪项权利，而不是只有「待上线」

- 企业主体、小程序备案、微短剧类目、激励广告位
- 逐剧版权、发行许可或报备、微信视频发布
- 腾讯云 VOD 子应用、转码/审核任务流、回调与防盗链
- 官方激励广告服务端验证是否可用

## 实验（有片源后再跑）

**实验 A：权益是否被理解**

- 假设：把 600 秒说成「约 N 集 + 过期时间 + 仅本剧」，完成广告的人多于只展示秒数的人
- 方法：5–8 人任务测试或内部真机对照
- 主指标：能复述规则的人数；广告尝试率
- 成功：多数人能复述且愿意看广告 → 固化文案
- 失败：觉得亏或看不懂 → 先改文案/数值，不先做跨剧钱包

**实验 B：按剧隔离是否成立（需要真实回访）**

- 假设：用户愿意为同一部剧再看广告，而不是立刻要别的剧
- 主指标：广告完成后 24 小时内回到同一部剧
- 失败：大量要换剧或弃用 → 再评估跨剧额度，作为独立决策，不夹带做推荐

## 停止或改方向

- 资质、类目或广告能力被拒且无替代路径：停止对外计划，工程冻结在内部工具
- 3 个月内拿不到至少 5 部含微信传播与广告变现授权的成片：暂停功能开发，只保留内容与合规工作
- 内部任务测试中无人愿意看完广告换继续看：先改交换规则，不扩量
- 外部灰度（若启动）出现内容安全或版权事故：立即停播
- 发布清单中的 D7 / 贡献毛利护栏：仅在有真实 cohort 后启用，不在 Mock 阶段用它们宣布成功或失败

## 复盘

- 工程收口完成后：是否首次提交、验证命令是否可复现
- 每取得一部候选剧或一项资质进展：更新内容盘点，不新增功能范围
- 第一次真机主路径跑通后：决定改文案、改数值，还是进入真实 provider 联调

## 明确不做（本周期）

推荐排序优化、搜索个性化、社交、弹幕、会员、支付、跨剧通用时长、管理端小程序、Android 客户端、把 `WECHAT_MODE`/`VOD_MODE` 改为 live 却不接真实实现。
