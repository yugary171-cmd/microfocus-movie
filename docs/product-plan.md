## 1. 执行摘要

**当前建议：有界收口 + 并行验证内容与交换规则。**

- 工程主线：保持已实现三端可内部联调、可恢复、可审计，不继续扩张功能。
- 产品主线：验证用户是否理解并接受“免费试看后，看完整广告换本剧限时观看时长”。
- 内容主线：确认至少一部可内部测试成片，并盘点 5–10 部候选剧的完整权利链。
- 商业化主线：只验证广告链路和单位经济所需数据，不用 Mock 广告证明收入成立。
- 发布主线：主体、类目、逐剧权利和真实 provider 未全部就绪前，不进入外部灰度。

### 本阶段必须回答的决策

1. 目标用户是否愿意用一次完整激励广告换取同一部剧的继续观看时间？
2. “前 2 集免费、600 秒、24 小时、仅本剧”中，哪些默认值需要调整？
3. 是否能取得合规内容和可信广告验证，使该模式具备外部验证资格？

产品负责人只在出现新的用户、内容、广告或合规证据后调整范围；工程完成度本身不能作为扩功能或上线的理由。

## 2. 用户问题与产品假设

**待验证的问题假设：** 一部分在微信内观看免费短剧的用户，看完试看后仍想继续观看同一部剧，并愿意用一次完整激励广告换取明确、限时的观看额度；平台则需要在广告净收入、内容授权成本和监管要求之间形成可持续闭环。

当前 workaround 是去抖音/红果等已有免费短剧产品，或付费/会员。本计划**没有**访谈或行为证据证明用户会为「微焦短剧」改路径。

## 3. 设计与实现边界

行业常见的「免费试看 → 广告解锁 → 继续观看」流程不能证明微信小程序里同一套秒数规则会被接受。

产品交互遵循：

- 短剧发现、试看、拦截和继续观看的交互顺序；
- 竖版封面、暗色观看环境、突出主操作等通用视觉原则；
- 用“约可看 N 集”帮助用户理解秒数权益。

禁止：

- 未经授权的第三方源码、布局、截图、图片、字体、APK、闭源 SDK、剧库、密钥、品牌或其他受限资源；
- “免后台”、客户端直接解锁、按集钱包、会员和单剧支付等实现或商业规则；
- 把其他产品可运行或可上架当成微焦短剧需求成立的证据。

观看端必须自绘并使用授权清晰的本地图标；PC 管理端保持工作台样式。本轮不因外部产品新增页面或发起视觉重构。

## 4. 证据台账

- **已知：** 前 2 集免费、一次广告 600 秒、24 小时过期、按剧 FEFO 账本已写入代码与契约；三端 MVP 已落地；真实 VOD 签名与激励广告服务端验证仍 fail-closed；发布与生产启动受合规闸门约束。
- **声称：** 该产品计划此前已确认。仓库内无用户研究、内容供给合同或类目批复。
- **假设：** 用户能理解并接受按剧秒数；能拿到含微信传播与广告变现授权的成片；激励广告有填充；600 秒能覆盖继续观看且单位经济不长期为负。
- **未知：** 精确目标用户；单集时长分布；eCPM、填充与单次广告净收入；内容供给来源；微信是否提供可用于生产的可信广告服务端验证。

任何“已知”项发生变化时应同步更新 `status.md`；任何假设被证伪时应优先调整交换规则或停止，而不是用新增功能掩盖问题。

## 5. 目标用户与场景（暂定，待验证）

首个可测试画像（不是市场结论）：

- 在微信内打开小程序、愿意先看免费集的短剧观众
- 触发：试看结束，想继续看同一部剧，但不想立刻付费
- 期望进展：用可接受的一次完整激励广告，换一段明确、会过期的继续观看时间

明确不作为首版承诺的用户：要跨剧通用额度的人、要会员去广告的人、要在管理端小程序里办公的运营。

## 6. 期望结果与指标

按阶段验证四件事：

1. **可理解性**：用户能否在无提示情况下说清奖励时长、有效期、适用剧目和未完成广告不发奖。
2. **可用性**：第 2 集能够正常完成，暂停、后台、缓冲和断网恢复不会错误扣费。
3. **交换意愿**：看完试看的人是否愿意开始并完整看完一条激励广告。
4. **持续价值**：看完广告后，用户是否在 24 小时内继续观看同一部剧，且真实单位贡献毛利没有持续为负。

在没有基线前，**不把**「500 激活 / 14 天 / D7=5%」当作已验证的成功线。那些数字保留在发布清单里，仅作未校准护栏，等第一批真实剧目校准后再升格为决策阈值。

内部阶段只看领先指标是否**有定义、能记下、能复盘**，不要求证明商业模式。核心漏斗必须区分：锁定拦截展示、广告点击、成功拉起、完整结束、可信验证通过、权益到账和广告后继续播放。Mock 广告**不能**当作收入证据。

## 7. 规则：底线与可调参数

账本必须可审计，数值可以在灰度前改，但改之前要记一次决策。

| 类型 | 项 | 说明 |
| --- | --- | --- |
| 底线 | 服务端是余额与播放许可的唯一事实来源 | 客户端不能改余额、不能持有长期播放地址 |
| 底线 | 奖励按不可变批次发放，不覆盖汇总余额；消费 FEFO；不出现负余额 | 见架构不变量 |
| 底线 | 免费集不扣权益；暂停/缓冲/后台不扣费 | |
| 底线 | 无资质、无逐剧权利、无真实 provider 时不得对外流量 | |
| 可调（v0 默认） | `FREE_EPISODE_COUNT = 2` | 可用文案和数值实验，不改账本模型 |
| 可调（v0 默认） | `REWARD_SECONDS = 600` | 应对用户说「还可看约 N 集」，避免只说秒数 |
| 可调（v0 默认） | `REWARD_TTL_SECONDS = 24h` | 过期文案必须可见 |
| 可调（v0 默认） | 额度仅限当前剧 | **最高风险的欲望假设**；未验证前不做跨剧通用池 |
| 实现约束 | 单活租约、5 秒心跳、15 秒断网宽限 | 优先观察是否误伤正常切聊天，而不是先加更严风控 |

## 8. 分阶段范围与出口条件

### Now：内部收口与问题验证

**目标结果：** 仓库保持可复现的内部联调状态，并拿到第一轮“有没有合规内容、用户懂不懂权益”的证据。

**时间盒（Timebox）：** 建议 1-2 周。若超时仍无法完成 5 人测试或确立责任人，则强制触发复盘。

**当前人工阻塞：** 产品负责人需先填写内容/合规、工程、数据和任务测试负责人，以及各自承诺日期。填写前可继续维护现有工程与文档，但不得把未分配任务报告为“进行中”，也不得进入 Next 或外部灰度。

工程维护范围（不加功能）：

- 保持管理端、API、观看端契约一致，持续通过 typecheck、test、build、迁移烟测和密钥扫描
- 修复阻断内部主路径的缺陷，不为 Demo 剧场、福利、社交占位增加正式后端
- 保持 Mock 与 live 边界；不把环境变量改成 live 冒充上线

产品与内容：

- 确认主体、类目、广告位和成片分别处于“已有 / 进行中 / 没有”的哪一状态
- 5–10 部候选剧权利盘点：授权主体、期限、微信传播、广告变现、转码、物料
- 播放器与「我的额度」文案：剩余约 N 集、过期时间、仅本剧有效、广告未看完不发奖
- 固定 5 人完成无提示任务测试：试看结束 → 理解规则 → 看广告 → 继续看 → 额度用尽/过期
- 使用固定样片和统一公式生成文案：`N = max(1, floor(600 / 该剧已发布集的中位时长秒数))`；文案保留“约”，样片、时长统计和文案版本随测试记录保存

**进入 Next 的条件：**

- 至少 1 部成片可合法用于内部测试，或有明确、可核验的 concierge 片源安排（如：使用公司内部宣传片、无版权争议的公开领域视频，仅用于走通播放与广告扣费链路，严禁对外传播）；
- 5 人测试中至少 4 人能无提示复述“仅本剧、约可看 N 集、24 小时有效、未看完不发奖”；
- 在明确可以不继续观看的情况下，至少 3 人主动选择广告路径；1–2 人选择时先调整交换文案或参数并重测，0 人选择时停止推进当前交换方案。该门槛只决定是否继续验证，不证明市场成立；
- 内部主路径没有阻断性缺陷，关键验证命令可复现。

### Next：真机与真实 provider 联调

**结果：** 真机跑通主路径，暴露可用性与风控误伤。

- 微信开发者工具 / 真机：登录、目录、播放、心跳、断网、前后台
- 广告失败、中途关闭、无填充：不发奖、可重试、提示可理解
- 下架后不再签发播放凭证
- 仅当企业账号、密钥、备案域名到位后，才做真实 `code2session`、VOD、广告服务端验证
- 若官方仍无可信广告校验：外部灰度保持关闭；`client_attestation` 只能用于经书面批准、明确标识的非生产内部技术验证，并记录残余作弊风险，不得作为商业化或外部用户验证证据

外部灰度前 P1 工作包：

- 完成基础分享、客服/反馈入口及“广告完成未到账”的 challenge 追踪与补偿闭环；
- 完成隐私指引、用户协议、账号注销、可删除数据清理和数据保留矩阵；
- 完成 provider 错误分类、核心漏斗埋点、指标口径和事故熔断演练；
- 为每项工作记录负责人、承诺日期、验收证据位置和超期升级人。未完成负责人分配时，Next 可以技术联调，但不得进入外部灰度评审。

**进入外部灰度评审的条件：**

- `release-checklist.md` 中“灰度启动前”的主体、类目、逐剧权利、隐私、安全和真实 provider 硬闸门全部有可核验证据；灰度样本、D7 和贡献毛利属于运行期目标与停止条件，不构成启动前循环依赖；
- 微信登录、VOD、广告验证、权益到账、心跳扣费和下架完成真机端到端验证；
- 数据口径、负责人、观察窗口、复盘日期以及停播/回滚责任人已确认。

### Later：仅由真实数据触发

- 推荐/个性化、跨剧额度、会员去广告、增长活动、更重的运营报表
- 没有第 2 集完播和广告完成数据前，这些都是猜测

## 10. 首版用户路径

1. 打开小程序 → 看到内部体验标识（Mock 时）→ 选一部剧。
2. 看完前 2 集免费内容；进度保存；暂停不扣费。
3. 第 3 集起被拦截，说明「看完一条广告，为本剧增加约 N 集、24 小时内有效」。
4. 广告未完成 / 无填充：不发奖，允许重试，已有额度不动。
5. 广告完成且可信验证通过：服务端幂等入账一笔 600 秒批次；验证仍在处理时保留原 challenge，不重复创建奖励。
6. 额度耗尽或过期：暂停并保留进度；过期批次不再可用。
7. 运营侧：权利与审核通过才能发布；下架立即停发新凭证。

## 12. 依赖、风险与未决问题

关键依赖：

- 企业主体、小程序备案、微短剧类目和激励广告位；
- 逐剧版权、发行许可或报备、微信传播与广告变现授权；
- 腾讯云 VOD 子应用、转码/审核任务流、回调与防盗链；
- 可用于生产的官方激励广告可信服务端验证。

主要风险及应对：

- **需求风险**：用户不接受按剧限时额度。先改文案或参数并重测，不直接建设跨剧钱包。
- **内容风险**：拿不到持续、完整授权的成片。暂停功能开发，优先解决内容供给。
- **平台风险**：类目、广告或可信验证不可用。外部灰度保持关闭，不用客户端证明绕过。

- **信任风险**：错误扣费、广告完成未到账或版权事故。立即熔断相关链路，保留审计证据并完成补偿或下架。

## 13. 实验计划

**实验 A：权益是否被理解**

- 假设：展示“约 N 集 + 过期时间 + 仅本剧”后，用户能正确理解权益规则，并有足够意愿继续验证广告交换
- 方法：每轮固定 5 人，其中至少 3 人在最近 30 天有微信内短视频或短剧观看经历；不预先解释规则
- 主指标：无提示完整复述规则的人数；在可自由退出时主动选择广告路径的人数
- 继续验证：至少 4 人完整复述规则，且至少 3 人主动选择广告路径
- 迭代重测：理解达标但仅 1–2 人选择广告，或有人误解为跨剧通用；先改文案或参数
- 停止当前方案：0 人选择广告，或连续两轮仍少于 3 人选择；重新定义交换规则，不先做跨剧钱包

**实验 B：按剧隔离是否成立（需要真实回访）**

- 假设：用户愿意为同一部剧再看广告，而不是立刻要别的剧
- 主指标：广告完成后 24 小时内回到同一部剧
- 前提：只能使用真实内容和真实行为数据；Mock 或内部操作记录不作为结论
- 决策：第一个完整真实 cohort 只用于建立基线，产品负责人必须在第二个 cohort 启动前冻结继续/迭代阈值；若用户主要要求换剧或直接弃用，则把跨剧额度作为独立产品决策，不夹带建设推荐

**实验 C：单位经济是否具备扩量资格**

- 假设：完整广告带来的净收入能够覆盖对应观看时长的内容、带宽、渠道、退款/补偿和运营成本
- 方法：按 cohort 记录广告净收入与增量观看成本，不使用标称 eCPM 替代实际到账
- 口径：单位贡献毛利 = 实际广告净收入 − 内容分成/授权摊销 − 增量带宽与转码成本 − 渠道及支付相关成本 − 补偿和可归因运营成本
- 账期说明：因微信广告结算存在 T+N 延迟，贡献毛利的最终判定以官方结算报表为准；灰度期可先使用预估 eCPM 建立监控看板，但停止扩量的决策必须基于真实结算数据
- 决策：连续两个完整 cohort 贡献毛利为负时停止扩量；样本不足时保持“未知”，不宣布模式成立

## 14. 停止、回滚与改向

- 资质、类目或广告能力被拒且无替代路径：停止对外计划，工程冻结在内部工具
- 自产品负责人确认启动内容获取之日起 3 个月内，仍拿不到至少 5 部含微信传播与广告变现授权的成片：暂停功能开发，只保留内容与合规工作
- 内部任务测试中无人愿意看完广告换继续看：先改交换规则，不扩量
- 外部灰度（若启动）出现内容安全或版权事故：立即停播
- 发布清单中的 D7 / 贡献毛利护栏：仅在有真实 cohort 后启用，不在 Mock 阶段用它们宣布成功或失败
- 错误扣费、重复发奖或奖励大面积不到账：立即熔断对应播放或奖励链路，完成账本核对后再恢复
- 回滚不删除权益账本和审计记录；停止签发新租约、新奖励或新内容，不通过清库掩盖事故

## 15. 责任与复盘节奏

- 产品负责人：确认范围、参数、实验结论、灰度、停止和恢复。
- 内容/合规负责人（待确认）：维护逐剧权利盘点和资质证据位置。
- 工程负责人（待确认）：维护验证证据、provider 就绪状态、熔断与恢复方案。
- 数据负责人（待确认）：冻结指标口径、观察窗口和 cohort 复盘结果。

复盘触发条件：

- 首轮 5 人任务测试完成；
- 任一关键资质、广告能力或候选剧状态变化；
- 第一次真实 provider 真机主路径跑通；
- 外部灰度每个完整 cohort 结束；
- 发生奖励、扣费、内容安全、版权或隐私事故。
