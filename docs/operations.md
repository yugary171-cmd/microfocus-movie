# 内容运营与事故处理

## 日常内容流程

1. 编辑创建剧目、填写权利资料元数据并上传材料引用。
2. 编辑为稳定集号创建媒体版本，从 API 获取短期签名后直传 VOD。
3. VOD 回调更新上传、转码和机审状态；失败时保留错误码并允许重试。
4. 审核员核对完整成片、权利范围、节目号和机审结果；不得审核本人创建的内容。
5. 媒体通过微信视频发布后，剧目进入 `READY`。
6. 管理员或获授权审核员执行发布；系统再次实时校验全部条件。
7. 到期任务自动下架；紧急问题由管理员立即下架并冻结新播放凭证。

业务记录只归档或下架，不硬删除。版权材料的实际文件应存入限制访问的私有存储，数据库只保存受控对象引用和校验摘要。

## 熔断级别

- 全局：停止全部奖励或锁定内容播放；用于平台、权益或内容安全事故。
- 用户：停止风险用户创建挑战或租约；不追扣、不产生负余额。
- 剧目：停止某部剧的奖励和播放；用于权利或内容问题。
- 广告位：停止一个广告位的新挑战；用于填充、回调或平台告警。

每次开关变更必须包含原因、操作者、工单引用和时间，并进入审计日志。

## 事故响应

### 版权或内容安全

1. 立即下架剧目并开启剧目熔断。
2. 保存当前版本、节目号、发布记录和访问审计，不修改历史证据。
3. 通知合规负责人，核对权利链或内容版本。
4. 只有新的完整审核记录通过后才能重新发布。

### 奖励异常

1. 开启广告位或全局奖励熔断，保留用户已有正余额。
2. 比对挑战、客户端完成、平台回调、grant 唯一键和广告结算。
3. 不通过追扣形成负余额；确需修正时使用带原因的补偿或人工冻结。
4. 修复后重放脱敏事件验证幂等，再小流量恢复。

### 播放地址泄露

1. 停止播放签发，轮换防盗链 Key。
2. 检查签名 TTL、IP/会话异常、空 Referer 和日志泄露。
3. 重新启用前确认旧链接已失效且客户端能处理 403 并重新申请租约。

## 灰度看板

至少展示：播放启动成功率、无崩溃会话、卡顿占比、第二集完播、广告加载/开始/完成/发放漏斗、奖励异常率、D1/D7、投诉率、每锁定内容观看小时贡献毛利，以及所有熔断状态。
