## 1. 当前结论

项目不是“功能还没做完”，而是已经完成了大部分 MVP 工程骨架，但还没有完成真实产品闭环。

当前推荐将目标限定为：

> 让一部具备内部演示条件的短剧，从管理端发布，经观看端目录/详情进入播放器，完成免费试看、广告挑战、权益到账和按秒播放扣减，并能在微信开发者工具和真机上被复核。

暂不以“可上线”“可商业化”或“用户增长”作为本阶段目标。

## 2. 证据与现状

### 已确认

- 三端代码存在：Vue 3 uni-app 观看端、Vue 3 PC 管理端、NestJS API；原生小程序保留为过渡实现。
- 管理端 Mock 发布路径已覆盖新建/编辑、媒体处理、审核、权利信息和内部发布。
- 观看端已有首页、剧场、搜索、福利、我的、目录详情和播放器主路径。
- `seed-drama-1 / 微焦之城` 已有 4 集样例；默认前 2 集免费，第 3/4 集需要本剧权益。
- 权益模型已包含挑战、幂等、限频、权益批次、FEFO 消费、播放租约和心跳扣减。
- 本地视频已转码为 H.264 Constrained Baseline、`yuv420p`、AAC-LC，并可通过局域网 Vite 服务返回 HTTP Range。
- 微信登录、激励广告前端适配和失败重试流程已有代码；客户端 `isEnded` 不直接等价于生产奖励。
- 生产启动已 fail-closed：缺少合规、真实微信/VOD provider 或服务端广告验证时不得启动生产模式。
- 当前全量验证通过：
  - `npm run typecheck`
  - `npm test`：admin 23、API 30、原生小程序 18、uni-app 31，共 102 个测试
  - `npm run build`
  - `npm run db:migrate:deploy`：无待执行迁移
  - `npm run db:seed`：命令成功

### 当前未闭环

- API 开发进程能启动并注册路由，但 `GET /health` 当前返回 HTTP 500；数据库健康检查尚未形成可复现的通过证据。
- 真机视频修复已有配置和编码侧修复，但手机重新编译后的人工验收仍需完成。
- 真实微信 `code2session`、激励广告服务端可信验证和腾讯云 VOD 上传/播放签名仍未实现；`verifyReward()` 与 VOD live provider 仍 fail-closed。
- 没有已确认的企业主体、微信类目/备案、广告位、域名、腾讯云账号和逐剧版权证据。
- 没有真实用户行为、广告填充、留存、收入或单位经济数据。
- 工作树仍有大量未提交改动和未跟踪的 `apps/uniapp` 等目录；这些改动的归属和最终提交范围仍需人工确认。

## 3. 用户问题与目标用户

### 暂定目标用户

在微信内打开小程序、愿意先看免费短剧，并在试看结束后考虑观看一条激励广告来继续看同一部剧的观众。

这是待验证画像，不是已证实的市场结论。

### 用户任务

1. 找到一部想看的短剧。
2. 明白哪些集可以免费试看，哪些集需要继续观看资格。
3. 看完一条完整激励广告后，明确知道获得了什么、有效多久、仅对哪部剧有效。
4. 在播放过程中暂停、切后台或网络波动时，不被错误扣减权益。
5. 额度耗尽或过期后，看到可理解、可恢复的提示。

## 4. 阶段目标与成功标准

### 阶段目标

在至少一部内部样例剧上，验证“内容发布 → 观看 → 广告交换 → 权益消费”的主路径是否可理解、可运行、可审计。

### 内部验证成功标准

- 产品负责人可从后台完成样例剧发布，并在观看端发现该剧。
- 微信开发者工具中可完成：首页 → 剧目详情 → 前两集播放 → 第三集拦截。
- 真机在同一局域网环境下可播放本地兼容视频，且不再出现已知黑屏。
- 广告未完整播放、中途关闭、无填充或服务端验证未完成时，不发放权益。
- Mock 验证模式下，完整广告挑战只创建一笔权益批次；重复提交不重复发奖。
- 600 秒权益显示为“约 N 集 / 24 小时 / 仅本剧有效”等可理解规则，且实际按播放进度扣减。
- 暂停、后台、缓冲和心跳重试不产生负余额或重复扣费。
- 下架或权利失效后，不再签发新的播放凭证。
- 所有上述结果有测试或人工验收记录，而不是仅凭页面可打开判断。

### 不作为本阶段成功标准

- 500 名激活、14 天运行、D7 留存或贡献毛利。这些数字在真实 cohort 前只是未校准护栏。
- Mock 广告完成次数、示例视频播放次数或后台页面数量。

## 6. 核心用户流程

### 6.1 发现与试看

1. 用户打开小程序，看到内部体验标识（Mock 模式）。
2. 用户从首页或搜索进入《微焦之城》详情。
3. 用户看到 4 集目录，其中第 1、2 集标记可试看，第 3、4 集标记需要继续观看资格。
4. 用户播放前两集，进度正常保存。

### 6.2 广告换继续观看

1. 用户点击锁定集。
2. 页面说明：完成一条激励广告，为本剧增加约 N 集观看时间，24 小时内有效。
3. 服务端创建与用户、剧目、广告位、设备/会话绑定的挑战。
4. 用户完整观看广告。
5. 客户端提交完成信号；服务端只有在可信验证通过后发放权益。
6. 权益以不可变批次写入本剧账本，重复请求返回同一结果。
7. 播放器取得短期租约，按心跳确认实际播放并扣减额度。

### 6.3 失败与恢复

- 用户中途关闭广告：不发奖，允许重新尝试。
- 广告无填充或加载失败：明确提示，不消耗已有额度。
- 服务端验证延迟：保留同一挑战，允许查询/重试，不创建新挑战。
- 网络中断：播放暂停；在宽限期内恢复，超时后要求重新取得租约。
- 额度耗尽或过期：保留进度，提示重新完成广告。
- 剧目下架或权利失效：停止签发新租约，并显示内容不可用原因。

## 7. 功能验收标准

### 管理端

- 只有具备权利、媒体和审核结果的剧目可进入内部发布状态。
- 发布、下架、审核和补偿操作写入审计日志。
- Mock 模式明确标识，不把演示登录或本地视频误称为生产能力。

### 观看端

- 首页、搜索、详情、播放器、我的页面能够串联。
- 前两集免费，锁定集不能通过直接构造播放器 URL 绕过拦截。
- 登录为显式操作；未登录页面不因 app 启动自动登录而消失。
- 真机本地视频地址只用于开发调试；生产播放不得依赖 `192.168.x.x` 或 loopback 地址。

### API 与权益

- 服务端是用户余额、播放许可和奖励状态的唯一事实来源。
- 奖励挑战具备过期、限频、幂等和重放保护。
- 生产模式中客户端 `isEnded` 不能单独触发权益。
- 播放租约短期有效；心跳必须校验租约、顺序、播放状态和当前剧目额度。
- provider 未完成时，生产请求明确失败并可观测，不静默降级为 Mock。

## 8. 指标与埋点

### 内部阶段只建立可测量性

| 指标 | 定义 | 阶段用途 |
| --- | --- | --- |
| 详情进入率 | 首页/搜索点击剧卡后成功进入详情的比例 | 验证发现路径 |
| 第 2 集完播率 | 开始第 2 集后完成播放的比例 | 验证内容与播放器 |
| 锁定集拦截理解率 | 任务测试中能复述权益规则的人数比例 | 验证文案 |
| 广告尝试率 | 触发拦截后点击广告的比例 | 验证交换意愿 |
| 广告完成率 | 广告开始后收到完整结束事件的比例 | 区分体验/填充问题 |
| 奖励到账成功率 | 完整广告后服务端可信验证并成功入账的比例 | 验证账本链路 |
| 广告后回看率 | 广告完成后 24 小时内回到同一部剧继续看的比例 | 验证按剧权益假设 |
| 错误扣费数 | 暂停、后台、缓冲或重复请求导致的错误扣费数 | 必须为 0 |

当前不设置虚假的用户规模或收入目标；获得真实 cohort 后再设基线、目标和停止线。

## 9. 风险、依赖与开放决策

### 最高风险

1. **真实广告验证不可用**：若微信没有可用的服务端可信验证/回调，生产发奖模型必须重新评审，不能直接放宽客户端证明。
2. **内容权利不足**：没有覆盖微信传播和广告变现的逐剧授权，工程完成也不能上线。
3. **真机网络与媒体链路不稳定**：本地 LAN 只能用于内部调试，不能作为发布方案。
4. **用户不接受按剧、按秒、24 小时规则**：没有用户任务测试前，不做跨剧额度或会员等复杂补偿。
5. **工作树边界不清**：未提交改动混合了多轮工作；提交前必须由人工确认文件归属和拆分范围。

### 需要人工决定

- 主体、类目/备案、广告位、域名和真实账号分别处于什么状态。
- 是否有至少 1 部可用于内部测试、且权利链完整的成片。
- 是否接受“先完成 Mock 内部闭环，再等待真实 provider”的推进策略。
- 第一次真机验收中发现问题后，优先修播放稳定性、文案理解还是广告验证。

## 10. 发布与停止条件

### 可以进入内部真机验证

- `npm run check` 通过。
- API `/health`、目录、详情、播放租约烟测通过。
- 至少 1 部样例剧可从后台发布到观看端。
- 真机首集和第二集可播放，锁定集拦截生效。

### 可以进入真实 provider 联调

- 企业账号、广告位、VOD 子应用、域名和测试密钥已由人工安全注入。
- 服务端广告验证和 VOD provider 有明确官方协议与回调验收证据。
- 不依赖 Mock 视频或 Mock 登录完成关键链路。

### 可以考虑外部灰度

- [发布清单](./release-checklist.md) 的主体、备案、类目、广告、版权、VOD、安全和监控硬闸门全部通过。
- 已完成真实 iOS/Android 微信真机、弱网、前后台、广告失败和下架演练。
- 有真实 cohort 基线，并由产品负责人确认灰度规模和停止条件。

### 应停止或转向

- 资质/类目/广告能力被拒且没有替代路径：停止外部发布，只保留内部工具。
- 三个月内没有至少 5 部覆盖微信传播和广告变现的成片：暂停新增功能，转向内容供给。
- 任务测试中多数人不愿完成广告或无法理解权益：先调整交换规则与文案，不增加推荐、会员或跨剧钱包。
- 发现版权、内容安全或重复发奖事故：立即停播并进入事故复盘。
