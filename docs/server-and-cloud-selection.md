# 微焦短剧：服务器与云服务选型简要说明

## 一、推荐结论

当前项目建议优先使用腾讯云 VOD，原因是现有后端已经按腾讯云 VOD 的接入边界设计，后续开发成本较低，也更适合当前微信小程序场景。

服务器不需要一开始购买很大，建议先从 2 核 4GB 开始，后续根据监控和用户量升级。

当前阶段没有服务器和域名，视频播放使用本地 Mock 模式，方便本地开发和微信开发者工具测试。Live 模式的代码和配置入口继续保留，等后续购买云服务并完成真实 VOD 配置后再切换。

## 二、推荐起步配置

| 服务 | 建议配置 | 用途 |
| --- | --- | --- |
| API 云服务器 | 2 核 4GB | 登录、剧目、权益、播放签名、评论等接口 |
| 云硬盘 | 40–80GB | 操作系统、API 程序和日志 |
| MySQL | 小规格云数据库，约 2 核 4GB | 用户、剧目、权益、播放记录 |
| 视频服务 | 腾讯云 VOD | 视频存储、转码、CDN 播放 |
| 域名 | 普通 `.com` 域名 | API、后台和官网访问 |

内部 Mock 开发阶段可以继续使用本地电脑，不必购买云服务器。

## 三、视频不要放在普通服务器上

普通服务器主要运行 API，不负责承载大量视频流量。

正式播放链路应当是：

```text
微信小程序 → API 服务申请播放权限 → 腾讯云 VOD/CDN 播放视频
```

这样可以避免视频流量压垮 API 服务器，也方便使用临时播放签名、防盗链和转码能力。

## 四、后期扩容方式

### 第一阶段：内部测试

- 使用 Mock 数据和本地视频；
- 不购买正式 VOD；
- API 和数据库可以运行在本地。

### 第二阶段：小规模上线

- API：2 核 4GB；
- MySQL：独立的小规格云数据库；
- 视频：腾讯云 VOD；
- 开启备份、监控和费用告警。

### 第三阶段：用户增长后

- API 升级到 4 核 8GB；
- 数据库增加内存、磁盘或只读节点；
- API 无状态化后增加第二台 API 服务器；
- 使用负载均衡分配请求。

腾讯云 CVM 支持调整 CPU、内存和云硬盘配置，但升级可能需要重启并造成短暂中断。云数据库 MySQL 支持调整实例规格、扩容磁盘和增加只读节点，具体以控制台当前可用配置为准。

## 五、费用主要看什么

视频项目的主要费用通常是播放流量，而不是 API 服务器。

需要重点关注：

- 视频播放流量；
- 视频存储容量；
- 转码时长；
- API 服务器；
- MySQL 数据库；
- 域名、备案和证书。

腾讯云 VOD 中国内地播放流量低阶梯约为 0.24 元/GB；腾讯云官方示例中，H.264 全高清转码约为 0.063 元/分钟，实际费用以控制台价格和资源包为准。

阿里云 VOD 的播放、存储和转码也可以使用，但本项目需要另外实现阿里云 VOD 的上传、播放签名、转码回调和媒体状态处理。

## 六、域名在哪里申请

域名可以在任意正规注册商购买，不要求和视频服务商一致：

- [阿里云万网域名注册](https://wanwang.aliyun.com/domain)
- [腾讯云域名注册](https://cloud.tencent.com/document/product/242)

建议使用一个普通 `.com` 域名，例如：

```text
microfocusmovie.com
api.microfocusmovie.com
```

域名注册后通常还需要：

1. 实名认证；
2. DNS 解析；
3. 中国大陆服务器对应的 ICP 备案；
4. 配置 HTTPS 证书。

## 七、最终建议

当前阶段不要购买大规格服务器。推荐顺序：

1. 继续使用 Mock 完成产品内部验收；
2. 选择腾讯云 VOD；
3. 正式小规模上线时购买 2 核 4GB API 服务器；
4. MySQL 使用独立云数据库；
5. 根据监控数据再升级到 4 核 8GB 或增加服务器。

本地 API 如需启动 Mock provider，可使用环境变量覆盖本地配置文件中的模式：

```bash
WECHAT_MODE=mock VOD_MODE=mock npm run dev -w @microfocus/api
```

uni-app 本地构建保持 Mock 客户端模式，不设置 `MICROFOCUS_CLIENT_MODE=live` 或 `MICROFOCUS_PUBLIC_API_URL`。正式环境再显式执行 Live 构建，并配置真实 HTTPS API 地址。

服务器可以后期升级，但升级操作可能导致短暂重启，因此正式环境应安排在低峰期执行，并提前做好备份和监控。
